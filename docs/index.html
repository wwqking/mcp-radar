MCP Server Evaluation Worksheet

Use this one-page worksheet before adopting a Model Context Protocol server, and revisit it whenever maintenance or installation signals change.

Scope: this is a screening workflow, not a security certification. Code review, permission review, and hands-on testing are still required.

1. Identity and source

Canonical source

  • Repository URL
  • Package or release URL
  • Documentation URL
  • License

Ownership

  • Named maintainer or organization
  • Issue response channel
  • Release ownership
  • Archived status

2. Maintenance evidence

  • Record the last meaningful release and commit, not just the most recent timestamp.
  • Review whether recent bug reports and pull requests receive useful responses.
  • Compare repository activity with package activity so a stale package is not mistaken for a maintained project.
  • Check the Weekly MCP Radar for lifecycle changes that should trigger a new review.

3. Installation and permissions

  • Install in a clean environment using the documented steps.
  • List every secret, filesystem path, network destination, and account scope requested.
  • Run one representative tool call and record the expected output.
  • Confirm that errors fail safely and do not expose credentials or sensitive content.

4. Decision record

  • Decision: adopt, monitor, re-evaluate, or reject.
  • Evidence date: when the repository, package, and instructions were checked.
  • Rollback: how the integration can be disabled or replaced.
  • Next review: a date or trigger, such as a new permission or archived repository.

Build a shortlist, then investigate

The MCP server leaderboard can help build an initial shortlist. The public scoring methodology explains the maintenance signals used for screening. Neither replaces your deployment-specific review.
