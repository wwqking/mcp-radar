# SEO Plan

## Executive Summary

MCP Radar should earn links with one stable, citation-ready health report rather than another round of mass directory submissions. The implemented report aggregates the current public dataset, names the sample boundary, exposes the source JSON, gives a suggested citation, and links every headline metric back to a reproducible method.

This campaign is not a keyword-expansion run. No volume, KD, traffic, or response-rate estimate is invented. The admission case comes from first-party data, live report/resource-page competition, and an existing competitor-backlink export. The same evidence produced a 100-target execution workbook: 30 editorial updates, 20 resource inclusions, 20 research/newsletter targets, and 30 maintainer-verification targets.

Funnel: 6 candidate page decisions → 6 intent/utility clusters → 1 create, 3 enrich, 0 merge, 0 noindex, 2 reject. Actionable priorities: 2 P0 and 2 P1.

## Site Scope

- Site: https://www.mcpradars.com
- Status: Existing bilingual Next.js directory and public-data product.
- Market: United States/global English first; Chinese secondary.
- Audience: Developers and AI teams evaluating MCP servers.
- Core problem: Raw directories show existence and breadth but often do not explain maintenance, lifecycle, provenance, or what was actually verified.
- Business: Transparent discovery and health screening for MCP servers.
- Monetization: Subscription/waitlist and sponsorship, kept separate from editorial scores.
- Safely inferred seeds: `mcp server health report`, `mcp ecosystem report`, `mcp server statistics`, `mcp server maintenance`, `best mcp server directories`.
- Known comparison domains: mcpcensus.com, presenc.ai, agentndx.ai, majorlabs.co, pulsemcp.com, mcp.so, mcp.directory, and mcpservers.org.

The current first-party snapshot is `data/servers.json`, dated 2026-08-02. It contains 1,977 server records mapped to 1,860 distinct declared repositories. These are server-record metrics, not a claim about the full MCP ecosystem.

## Opportunity Summary

Live results collected on 2026-08-03 show that the “state of MCP” space already contains strong reports:

- MCP Census emphasizes full-registry scale and reports 15,382 servers.
- Presenc AI publishes a broad adoption/statistics report.
- AgentNDX publishes a curated state-of-ecosystem article.
- Major Labs publishes a trust-index PDF.
- Pinaka and current academic papers focus on security measurement.

That makes a generic “MCP ecosystem report” a strong SERP, not an easy keyword page. MCP Radar’s defensible opening is narrower: a continuously reproducible health sample with record-level JSON, explicit lifecycle rules, repository/package/remote signals, and unusually visible limitations. The page is admitted because it has a plausible route to citations and can be maintained from existing first-party data—not because a volume number says to create it.

Live resource pages from OpenHelm, ServiceGraph, AutomationSwitch, Dynomapper, MCP360, and others compare MCP directories but do not yet consistently include a maintenance-first public-data source. Existing backlink exports also show that relevant publishers and resource pages have previously linked to competing directories with ordinary Follow links. That is historical evidence for target selection, not a guarantee about future placement.

## Site Architecture

- Canonical citation asset: `/en/mcp-server-health-report` and `/zh/mcp-server-health-report`.
- Public record-level source: `/dataset.json`.
- Method definition and corrections: `/en/about` and `/zh/about`.
- Interactive supporting data: `/en/leaderboard`, `/en/radar`, and localized equivalents.
- Discovery surfaces: sitemap, footer, and `llms.txt` point to the report.
- The report uses one stable evergreen URL. Do not generate monthly URLs that fragment citations; update the snapshot date and contents in place.

Implemented differentiation:

1. Original first-party aggregation from the current MCP Radar dataset.
2. Explicit separation of server records and distinct repositories.
3. Narrow lifecycle definitions and a visible “active is not certification” boundary.
4. Dynamic growth/category/lifecycle tables instead of static claims.
5. Downloadable JSON, citation text, Dataset + Article schema, and bilingual presentation.

## Priorities

1. P0 — Publish and verify the health report page from the current dataset.
2. P0 — Make `/dataset.json` name the report and keep record-level sources reproducible.
3. P1 — Cross-link the report from the methodology page so claims and definitions stay connected.
4. P1 — Cross-link the report from the leaderboard, sitemap, footer, and `llms.txt`.
5. P0 execution — Work the 55 P0 prospects in the campaign workbook first, starting with editorial/resource targets that have historical Follow evidence.

Rejected decisions:

- Do not create dated monthly report URLs; they would split links and require redirects/merges later.
- Do not create a paid “guaranteed dofollow” offer or buy ranking links. Paid or sponsored placements must be qualified, and they are not the campaign’s success criterion.

## 30/60/90-Day Plan

Days 1–30:

- Publish the report and verify both locales, schema, sitemap, dataset JSON, and internal links.
- Recheck the top 20 P0 target pages for accessibility, author identity, topical fit, and current outbound-link attributes.
- Send personalized outreach in batches of five. Use one page-specific observation and one relevant fact per message.
- Contact maintainers as a data-correction request first; mention an official-docs citation only after accuracy is confirmed.
- Record every touch, reply, earned link, attribute, and referral visit in the workbook.

Days 31–60:

- Follow up once on unanswered P0 outreach, then stop.
- Update the report from the next dataset snapshot without changing its URL.
- Publish one chart-ready excerpt only if recipients repeatedly request it; keep the report canonical.
- Compare response and link rates by segment, but do not generalize from tiny samples.

Days 61–90:

- Expand only the segment that earns editorial links or meaningful referrals.
- Revalidate every earned link and distinguish standard Follow, `ugc`, `nofollow`, and sponsored links.
- Add newly cited claims to a change log and preserve the snapshot date used by each citation.
- Reject low-quality or paid opportunities that cannot meet editorial and policy standards.

## Assumptions and Pending Evidence

1. Keyword Magic was not rerun because this is a link-earning asset decision, not keyword-footprint expansion. Search volume and KD for the report phrase remain pending and are not required for page admission.
2. GSC and analytics exports were unavailable, so existing rankings, referral traffic, and assisted subscription conversions are pending.
3. Competitor backlink exports are dated 2026-08-01. Follow status proves only the observed competitor link at that time; each target must be rechecked before outreach.
4. Live SERP evidence was collected on 2026-08-03 in global English results and is not a complete country-specific ranking study.
5. The dataset changed during execution from the 2026-07-30 snapshot to the 2026-08-02 snapshot. Final artifacts use the latter; the report code calculates values dynamically.
6. Current records lack explicit `officialRegistryVerifiedAt` fields. The report treats that status as unknown and counts only explicitly verified values, rather than converting missing data to false claims.
7. Actual author contact details, replies, placements, link attributes, and referral results remain execution evidence; the workbook initializes them as not started.
